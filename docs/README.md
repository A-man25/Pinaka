# PINAKA Engine — Project Forge

A C++20 engine, Studio application and tests, generated by Premake5.

## One entry point per operating system

**Windows:** double-click `build/launcher/LaunchPinaka.bat`.

**macOS:** open `build/launcher/LaunchPinaka.command` (or run `bash build/launcher/LaunchPinaka.command`).

The launchers locate the repository by their own path; cloning anywhere works.

## Migration required once for your existing 2026 checkout

1. Commit/back up your current changes.
2. Extract this package **into the existing PINAKA repository root**, preserving paths.
3. Run `build/setup/MigratePinaka.bat`, or select menu **9** from the new launcher.
4. Review `git status` to see the moves.
5. Run the launcher again, select **3** to generate projects, **1** to build/run Debug.

See [MIGRATION.md](MIGRATION.md) for the exact file moves.

## Repository layout

```text
PINAKA/
  .gitignore / .gitmodules          # Git-owned metadata (unchanged submodule path)
  src/
    PinakaEngine/Pinaka/...    # Core, Foundation, Platform
    PinakaStudio/Studio/...    # Studio executable sources
  tests/TestApp/...            # Tests executable sources
  build/
    launcher/                      # Windows + macOS entries and animated UI
    setup/                         # One-time migration, platform setup
    premake/premake5.lua          # SINGLE build definition
    scripts/                       # Platform build/clean support
    bin/  obj/                     # GENERATED: ignored
    legacy/                        # Old scripts/projects: ignored, until reviewed
  proj/                            # GENERATED IDE solutions: ignored
  ide/vscode/Pinaka.code-workspace # Workspace-scoped tasks + debugging
  docs/                            # Readme, original docs and Architecture PDFs
  thirdparty/GLFW/glfw             # Git submodule path stays unchanged
  thirdparty/Premake               # Existing Premake license/optional binary
```

Unlike the old `setEnv.bat`, Premake **does not create source folders**. New source files are discovered recursively in the existing `src/` and `tests/` trees when you regenerate.

## Tools and prerequisites

- Windows: Git for Windows, Visual Studio with **Desktop development with C++** (MSBuild), Premake5 (portable executable or PATH), optional VS Code.
- macOS: Xcode Command Line Tools, Git, Premake5, optional VS Code; native engine build still needs a macOS window/platform implementation.
- Premake on Windows may be downloaded from the **official Premake GitHub release** on first launch, after your consent. This requires internet access.
- Git submodule checkout is automatic when Git is installed and source is available.

VS2022 generation is the safe default; Visual Studio 2026 can generally open the generated VS2022 solution. A native `vs2026` action is offered **only if your installed Premake actually supports it**.

## Windows launcher commands (also usable from VS Code)

```bat
build\launcher\LaunchPinaka.bat
build\launcher\LaunchPinaka.bat setup
build\launcher\LaunchPinaka.bat generate vs2022
build\launcher\LaunchPinaka.bat build debug
build\launcher\LaunchPinaka.bat buildrun release
build\launcher\LaunchPinaka.bat diagnose
build\launcher\LaunchPinaka.bat clean
```

Generated solution: `proj/vs2022/Pinaka.sln`. Executable (Debug): `build/bin/Debug-windows-x86_64/PinakaStudio.exe`.

VS Code: open `ide/vscode/Pinaka.code-workspace`; use `Ctrl+Shift+B` to build Debug. VS Code cannot magically install the MSVC toolchain; that requirement remains.

## macOS status

The scripts and GLFW Cocoa backend configuration are supplied, with Premake `gmake2` generation and VS Code launch. **The supplied PINAKA sources only contain `WindowsWindow.cpp`, so macOS engine build and run are not yet verified or complete.** Add a real macOS platform window implementation and adjust engine factory/entry code before expecting that target to run. The launcher explicitly blocks building when that platform directory is absent.

## Limitations

The ZIP does **not** contain your full engine source tree; it supplies new tooling and a script to move your existing files locally. Actual Windows compilation and macOS runtime were **not executed** in this environment. Keep `build/legacy/` until you've validated the migrated build, then remove it when safe.
